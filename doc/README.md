## 每包文档

每个业务包维护四份文档：

| 文件 | 用途 |
|---|---|
| `needs.md` | 使用者是谁、解决什么问题、有哪些功能、明确不做什么 |
| `rules.md` | 规则编号、计算方法、异常情况和确认样例；没定的问题标"待确认" |
| `changes.md` | 已确认的变化、生效时间、对旧数据和接口的影响 |
| `flows.md` | 从代码生成的接口、步骤、字段来源和数据表 |

规则的预期值由产品确认，测试使用对应的样例；未知的业务含义不要自行补齐。手写的业务文档每份不超过 200 行，变长了就按主题拆分，业务条件要保留。生成的文档不要手工修改。

生成的汇总结构：[接口](api/index.md)、[模块关系](modules.md)、[开发计划](development.md)、[规则进度](progress.md)。它们说明的是声明和计划；实际的检查与运行情况要用项目 Skill 的命令查询。没做完的事使用项目已有的任务记录；需要产品任务清单时再创建，模板不预置历史。

# 用户权限：规则

以下为通用模板的默认规则。用户已授权补齐通用能力；具体项目启用前仍需检查组织和权限划分。

### R-01 组织

组织代码由小写字母、数字和短横线组成，长 3 至 32 字符，全系统唯一。只有拥有 `user_access.system` 权限且组织范围为 `*` 的调用者能创建组织。名称去掉首尾空白后保存。

| 输入 | 结果 |
| --- | --- |
| 代码 `north`、名称 ` 北区 ` | 创建代码为 `north`、名称为 `北区` 的组织 |
| 再次创建 `north` | 返回代码冲突 |

### R-02 角色与用户

角色只属于一个组织，名称在组织内唯一；角色保存权限名列表。授予角色的权限必须是授予者自己拥有的权限；`user_access.system`、`system.diagnostics`、`system.jobs`、`system.*` 能看到或操作全部组织的数据，只能配给组织范围为 `*` 的服务密钥，不能放进组织角色。`system.audit` 只返回本组织的审计记录，可以放进组织角色。用户在同一组织内以用户名唯一识别，密码用 scrypt 保存。组织管理员只能管理自己的组织；跨组织或没有组织编号的请求被拒绝。停用用户后不能再登录，已经签发的令牌在有效期内仍可使用。

| 输入 | 结果 |
| --- | --- |
| 北区创建角色 `viewer`，权限 `product_catalog.read` | 北区用户可被分配这个角色 |
| 北区管理员请求南区用户列表 | 拒绝访问 |
| 只有 `user_access.manage` 的北区管理员创建含 `product_catalog.write` 的角色 | 拒绝访问：超出自己的权限 |
| 任何调用者创建含 `system.diagnostics` 的组织角色 | 拒绝访问：跨组织的系统权限 |

### R-03 登录和令牌

登录同时核对组织代码、用户名、密码和启用状态。失败统一返回“账号或密码不正确”，不说明哪一项存在。成功后签发有效期 60 分钟的 HS256 令牌，包含用户编号、组织编号和签发时的权限；校验签发方、接收方和过期时间。角色或用户状态变化在旧令牌到期后生效。

| 输入 | 结果 |
| --- | --- |
| 正确的组织代码、用户名和密码 | 返回令牌和到期时间 |
| 错误密码或停用用户 | 返回相同的登录失败错误 |

### R-04 管理权限

创建、查询和调整用户或角色需要 `user_access.manage`；创建组织需要 `user_access.system`。组织范围 `*` 的系统管理员可查看全部组织，普通管理员仅能查看自己的组织。接口返回用户信息时不返回密码摘要。

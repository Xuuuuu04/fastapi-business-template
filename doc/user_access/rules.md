# 用户权限：规则

以下为通用模板的默认规则。R-02 的授权限制于 2026-09-24 经用户确认；R-03、R-05 至 R-07 按用户要求采用行业通行做法（OAuth 2.0 安全最佳实践 RFC 9700、OWASP 令牌建议）。具体项目启用前仍需检查组织和权限划分。

### R-01 组织

组织代码由小写字母、数字和短横线组成，长 3 至 32 字符，全系统唯一。只有拥有 `user_access.system` 权限且组织范围为 `*` 的调用者能创建组织。名称去掉首尾空白后保存。

| 输入 | 结果 |
| --- | --- |
| 代码 `north`、名称 ` 北区 ` | 创建代码为 `north`、名称为 `北区` 的组织 |
| 再次创建 `north` | 返回代码冲突 |
| 代码 `North` 或 `a_b` | 返回格式错误 `org_code_invalid` |

### R-02 角色与用户

角色只属于一个组织，名称在组织内唯一；角色保存权限名列表。创建角色、创建用户或调整用户角色时，角色的全部权限必须是授予者自己拥有的权限；已有角色也必须检查，不能通过分配别人创建的角色超出自己的权限。全组织全权限的系统管理员仍可分配组织角色；角色不存在或不属于目标组织时返回 `user_access_missing`。`user_access.system`、`system.diagnostics`、`system.jobs`、`system.*` 能看到或操作全部组织的数据，只能配给组织范围为 `*` 的服务密钥，不能放进组织角色。`system.audit` 只返回本组织的审计记录，可以放进组织角色。用户在同一组织内以用户名唯一识别，密码用 scrypt 保存。组织管理员只能管理自己的组织；跨组织或没有组织编号的请求被拒绝。停用用户后不能再登录，他的全部刷新令牌立即作废，已经签发的访问令牌最多 15 分钟后失效（R-05）。调整角色后，新权限在用户下一次刷新时生效，最长 15 分钟。

| 输入 | 结果 |
| --- | --- |
| 北区创建角色 `viewer`，权限 `product_catalog.read` | 北区用户可被分配这个角色 |
| 北区管理员请求南区用户列表 | 拒绝访问 |
| 只有 `user_access.manage` 的北区管理员创建含 `product_catalog.write` 的角色 | 拒绝访问：超出自己的权限 |
| 任何调用者创建含 `system.diagnostics` 的组织角色 | 拒绝访问：跨组织的系统权限 |
| 只有 `user_access.manage` 的北区管理员把系统创建的 `file_library.write` 角色分给新用户或已有用户 | 返回 403；用户不创建、原角色和启用状态不变 |
| 北区管理员把仅含自己拥有权限的已有角色分给新用户或已有用户 | 成功 |
| 全组织全权限的系统管理员分配北区的 `file_library.write` 角色 | 成功 |
| 北区管理员分配南区角色或不存在的角色 | 返回 `user_access_missing`；请求管理南区用户则返回 403 |

### R-03 登录和令牌

登录同时核对组织代码、用户名、密码和启用状态。失败统一返回“账号或密码不正确”，不说明哪一项存在；同一组织、用户名和来源地址连续失败 5 次后，15 分钟内拒绝登录；同一组织和用户名不论来源地址，15 分钟内累计失败 20 次后同样拒绝登录，防止换地址持续猜密码。达到上限期间正确密码也会被拒绝，这是有意的临时限制（参照 OWASP 认证建议：限时节流而不是永久锁定），15 分钟后自动恢复。成功登录后两项计数都清零。成功后返回访问令牌和刷新令牌（R-05）。访问令牌为 HS256 签名，有效 15 分钟，包含用户编号、组织编号和签发时的权限；校验签发方、接收方和过期时间，不查数据库。更换签名密钥时，旧密钥可以在过渡期内继续用于校验。

| 输入 | 结果 |
| --- | --- |
| 正确的组织代码、用户名和密码 | 返回 `access_token`（15 分钟）、`refresh_token`（7 天）和各自剩余秒数 |
| 错误密码或停用用户 | 返回相同的登录失败错误 |

### R-04 管理权限

创建、查询和调整用户或角色需要 `user_access.manage`；创建组织需要 `user_access.system`。组织范围 `*` 的系统管理员可查看全部组织，普通管理员仅能查看自己的组织。接口返回用户信息时不返回密码摘要。用户列表按编号从小到大按位置续读：每页最多 100 条，返回下一页的位置，最后一页的位置为空。

### R-05 刷新令牌与登录会话

一次登录形成一个登录会话。刷新令牌是 256 位随机值，数据库只保存 SHA-256 摘要。刷新令牌 7 天不用就失效；一次登录最长保持 30 天，之后必须重新输入密码。每次刷新都换一个新的刷新令牌，旧的随即作废，同时按用户当前的启用状态和角色权限签发新的访问令牌。已经用过的刷新令牌再次被提交，说明它可能被盗用，这次登录会话的全部刷新令牌立即作废，用户需要重新登录。退出登录作废这次登录会话；令牌无效时同样返回成功，不暴露令牌是否存在。

| 情况 | 结果 |
| --- | --- |
| 用 7 天内的刷新令牌刷新 | 返回新的访问令牌和新的刷新令牌，旧刷新令牌作废 |
| 旧刷新令牌已经换过新令牌，又被提交 | 拒绝；刚换出的新刷新令牌也一起作废 |
| 用户已停用，或退出登录后再刷新 | 拒绝，提示重新登录 |
| 同一个刷新令牌被两个页面几乎同时提交，两次检查都显示可用 | 首次可返回新令牌；第二次保存时按重复使用处理并作废整组，包括首次返回的新刷新令牌，两个页面都要重新登录；前端应当只让一处负责刷新 |
| 刷新令牌在检查后、保存前已过期或退出登录 | 拒绝；不签发新令牌，保持正常过期或退出语义 |

### R-06 修改自己的密码

已登录用户提交原密码和新密码（8 至 256 个字符）。原密码不正确时拒绝，不做任何修改。修改成功后，这个用户的全部登录会话作废，所有设备都需要用新密码重新登录。服务密钥不是用户，不能使用这个操作。

| 输入 | 结果 |
| --- | --- |
| 原密码错误 | 返回“原密码不正确”，密码不变 |
| 原密码正确 | 密码更新；旧刷新令牌失效，旧密码不能再登录 |

### R-07 清理刷新令牌记录

系统任务每天 04:00 删除过期或作废超过一天的刷新令牌记录，保留一天供排查。

### R-08 管理员发放重置码找回密码

模板不带邮件、短信，找回密码由管理员协助：有 `user_access.manage` 权限的管理员为本组织的用户生成一次性重置码，通过线下或自己的渠道交给用户。重置码是 128 位随机值，数据库只保存 SHA-256 摘要，30 分钟内有效，只能用一次；为同一用户再次生成时，之前没用过的重置码作废。用户提交组织代码、用户名、重置码和新密码（8 至 256 个字符）即可设置新密码，这个用户的全部登录会话随即作废。重置码不对、过期、已用过或与账号不符，统一返回“重置码无效或已过期”，不说明是哪一种。两步验证不因重置密码而关闭。

| 情况 | 结果 |
| --- | --- |
| 30 分钟内用重置码设置新密码 | 新密码生效，旧密码和旧登录会话失效 |
| 同一重置码再用一次 | 返回“重置码无效或已过期” |
| 生成新重置码后用旧的 | 返回“重置码无效或已过期” |

### R-09 两步验证

用户可以开启基于时间的一次性验证码（TOTP，RFC 6238，30 秒一个 6 位数字，可用常见的身份验证器应用）。开启分两步：先生成密钥（返回密钥和可扫描的地址），再提交应用中显示的验证码确认，确认后才生效。密钥用 `APP_DATA_KEYS` 加密后保存。

开启后登录需要同时提交验证码：没有提交返回“需要两步验证码”（不计入登录失败次数）；验证码错误按登录失败处理。允许前后各差一个 30 秒周期；同一个验证码只能用一次，已用过的周期及更早的验证码都拒绝。用户可以提交当前验证码关闭两步验证；手机丢失时，由本组织管理员关闭，关闭记入变更历史。

| 情况 | 结果 |
| --- | --- |
| 开启后只提交密码 | 返回 `otp_required`，不签发令牌 |
| 密码和当前验证码都正确 | 登录成功 |
| 同一个验证码再次登录 | 按登录失败处理 |
| 管理员为用户关闭两步验证 | 用户之后只需密码即可登录 |

# development：开发状态的数据与视图

`tools.project` 的实现。项目计划来自根目录 `project-plan.json`，实际结构来自模块声明，
测试结果来自 `tools.check` 保存的本机记录。三者分开保留，并按模块与操作名对应。

- `plan.py`：检查计划格式；业务线与开发包只影响阅读和分工，不改变模块导入路径。
- `history.py`：计算包含声明依赖的代码版本、保存检查轮次、选择各数据库最近的测试结果。
- `versions.py`：总登记的读取与中性化、模块接口文件归属和读取缓存；`history.py` 的版本计算用它组成公共与模块两部分。
- `evidence.py`：识别完整检查范围和测试来源版本，局部成功不覆盖全量失败。
- `scenarios.py`：原规则表的确认样例对应实际测试结果，过期、跳过和失败分别保留。
- `summary.py` 与 `attention.py`：项目/单包摘要、问题预览、当前来源与历史结果计数；具体操作和测试按需读取。
- `commands.py`：工具生成的继续读取命令保留外部检查目录，不改原始运行证据。
- `impact.py`：按声明计算直接、传递和后台调用方；接口主题文件按登记模块归属，公共入口保守建议全量。
- `design.py`：生成可提交的静态设计说明，不读取本机检查或数据库。
- `status.py`：比较计划、已登记操作、测试与成功执行记录。
- `views.py`：生成 Markdown 与 Mermaid，模块详情包含条件、规则、源码和计算图。
- `runtime.py`：按需读取数据库中的近期运行，对应当前源码摘要，给出耗时、产出形状、SQL 和运行图，不输出业务数据。

测试运行记录不保存令牌、数据库地址或步骤取值。每个步骤记录文件、函数、时间、字段产出形状和数据库调用。
模块图可叠加同一次实际测试的状态；不能把几次执行的不同分支拼成一次成功。
`server/var/development/` 是本机资料，
不同机器不会自动共享；CI 可将它作为检查附件。历史轮次只表示留存的检查次数。

`--runs` 的近期成功样例覆盖分母来自计划，包括未实现操作，明确关闭的模块除外；缺少计划或数据库记录入口时未知。
旧版本成功不计入当前源码，无记录的操作不能据此判定正确或错误。当前版本成功执行也不等于业务规则已经完整验收。

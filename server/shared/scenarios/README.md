# 样例与观察

ObservationJournal只在样例主动capture时记录实际取值，普通请求不产生原文观察记录。地址带操作、步骤、字段和可选批次、成员、尝试；真实执行顺序统一编号。

期望单独来自确认规则。比较器先报告最早实际观察到的不一致，未记录位置标unknown，同一位置重复执行而没有足够区分时标ambiguous。公共summary和repr不保存取值，不能用摘要代替完整协议或业务断言。

输入、初始数据库状态、最终结果和外部副作用的预期保存为独立样例资料，正式业务实现不能从这些预期生成。观察原文涉及敏感数据时只在本机私有样例环境启用。

## 写法

在步骤声明里加 `observes=["字段名"]`，字段必须已经在本步骤的读写范围里。测试用 `with capture(journal)` 包住真实运行，再用 `ExpectedObservation` 写独立预期。后台执行器传入持久成员键和尝试号，分段执行器传入实际批次；未完成步骤没有虚构观察结果。数据库前后状态、发送次数和重启后状态要另外断言，中间字段匹配不能代替这些检查。

独立样例放在 `doc/业务包/cases/*.json`，包含完整编号、input、initial、expected、database、effects、observations、assertions和tests。tests引用准确测试函数。规则明确确认时，开发命令保存样例内容、关键assert表达式、参数化输入和断言引用的局部赋值摘要，辅助函数与说明仍可修改。它不证明外部辅助函数的所有语义，也不验证确认者身份。普通开发检查核对已确认内容，交付检查另外要求高风险规则已确认；历史Git基线也参与比较，不能只重算当前摘要。

`dev rules confirm_sheet`生成确认单，`adopt_markdown 业务包`采纳历史文本，`supersede 规则编号 --text 新内容 --source 新来源 --reason 变更依据`保留修订。原始材料保持本机私有，提交前要人工确认样例已脱敏。

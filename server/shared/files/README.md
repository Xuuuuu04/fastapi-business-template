# 文件存储底层

`storage.py` 提供本地目录和 S3 兼容存储；`uploads.py` 接收临时上传，限制大小和扩展名；`gate.py` 给模块的存储实现提供带模块前缀的文件操作。文件记录、权限和下载接口由产品的业务模块管理。正式的存储键不能包含 `..`。存储实现支持按模块前缀逐项列出对象，供后台任务清理没有文件记录的对象。

`ModuleFiles.read_upload(temp_id, max_bytes)` 有界地读取临时原件，不移动文件；`discard_upload` 清理业务已确认的重复上传。`save_bytes` 保存模块自己生成的内容，`exists` 检查正式文件；存储键仍然限定在模块前缀里。文件变大之后，读取的上限依然有效。

## 不可变原件与批次

`files.freeze(temp_id)`返回ArtifactRef，包含组织与模块内的摘要键、大小和SHA-256。原件先冻结私有快照，再保存一次；同内容并发上传得到相同引用。普通save/adopt接口不能覆盖artifacts目录，现有文件保存方法仍用于可更新业务文件。

每批通过`files.read_window(ref, offset, length, max_bytes=...)`读取有限窗口。本地直接seek，S3使用Range并核对ContentRange，避免每批从头读全文；批次游标只保存offset与原件引用。跨模块或组织引用会被拒绝，业务模块仍须先核对业务记录的所有权。

`files.open_artifact(ref)`流式读取并在末尾核对完整摘要，最终发布前必须消费到结尾。窗口读取依靠已经冻结的不可变摘要键，不声称外部手工替换对象仍然可信。上传临时区、正式原件与任务引用分别管理，清理需要保留任务和规则样例引用的证据。

自定义FileStorage适配器在3.0需要实现open_range；不得使用全文读取再切片来伪装范围读取。公开接口升级步骤在最终3.0迁移说明中汇总。

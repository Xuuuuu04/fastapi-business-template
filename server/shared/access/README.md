# access：调用者身份与权限

- [caller.py](caller.py)：`Caller`（编号、种类、名称、组织、权限）。权限写作“模块名.动作”，`模块名.*` 表示该模块全部权限，`*` 表示全部权限。
- [keys.py](keys.py)：服务密钥。配置里只保存 SHA-256 摘要和权限，用固定时间比较；新密钥用 `fastapi_operations.make_key` 生成。
- [tokens.py](tokens.py)：签发并校验 HS256 用户令牌，校验签发方、接收方和到期时间。
- [audit.py](audit.py)：操作成功、失败和权限拒绝的操作记录的身份、状态和时间，不保存业务正文。

## 规则与原因

- 身份只来自已验证的凭据，请求正文里自报的身份一律不用。
- 匿名调用受保护的操作返回 401；有身份但缺权限返回 403。
- 本地开发身份（`APP_DEV_CALLER`）只在 `local` 环境生效，生产环境开启会拒绝启动。
- 任务执行时，服务密钥按当前配置重新取得权限；密钥被删除后，排队中的任务不再执行。
- 公共能力提供令牌签发和校验；用户密码登录、角色与状态管理由产品业务实现。
- 生产环境的当前与轮换旧 JWT 密钥都必须独立设置，不能使用模板公开的开发密钥。轮换时只保留实际使用过的生产密钥，过渡结束后移除。
- 服务密钥可通过 `--org-id` 指定组织；空组织范围不能访问按组织隔离的表。

## 字段加密

[vault.py](vault.py)：存储实现的构造参数写 `vault` 就能拿到 `Vault`，`vault.encrypt(文字)` 后再写库，读出后 `vault.decrypt(...)`。密钥来自 `APP_DATA_KEYS`：第一把加密，全部都能解密；换密钥时新密钥放前面、旧密钥放后面。生产环境必须设置独立的密钥。

# modules：操作约定、模块声明与启动检查

## 负责

| 文件 | 内容 |
| --- | --- |
| [contract.py](contract.py) | `contract()`：模块对外操作的约定，写在模块的 public.py |
| [module.py](module.py) | `Module`：模块声明，写在模块的 module.py |
| [checks.py](checks.py) | 启动时检查全部模块声明 |
| [catalog.py](catalog.py) | `Catalog`：检查通过后固定下来的模块目录 |
| [layout.py](layout.py) | 固定文件位置和结构说明；生成器、旧包采用命令与默认启动共用 |

`Module.endpoints` 和步骤的 `endpoints` 登记上游协议，公共对象可以跨包复用；协议的内容、效果和步骤引用都会进入声明摘要。详见[外部接口](../remote_calls/README.md)。

## 为什么这样登记

- 全局只在 `app/setup/catalog.py` 列出启用哪些模块；操作、流程、任务、提示词都写在模块自己的 module.py，只写一次。
- 模块之间的依赖从步骤的 `uses` 推出来，不另外登记，避免两份登记互相对不上。
- 启动检查一次列出全部问题：名称格式、操作归属、权限命名、调用了未启用的模块、循环依赖、表名前缀、提示词文件、任务和定时计划。任一项不通过，服务不会启动。

## 注册检查和资源权限各管什么

注册检查回答“这段代码能不能调用这个操作”；“这个调用者能不能访问这份数据”是资源权限，在业务步骤中用 `caller` 检查，两者都要通过。

## 业务别名与定位

`Module(..., aliases=("价格表", "调价", "price table"))` 声明模块的业务词；`contract(..., aliases=("调整售价", "/api/v1/price/old"))` 声明操作的别名和历史路径。别名是可选的，不改变调用名、HTTP 路由或短操作的行为。别名直接附着在登记项上，删除操作时别名一起删除，没有需要另外同步的引用表；已失效的步骤、任务、流程操作引用沿用原来的启动检查。模块别名全局唯一，操作别名在所属模块内唯一；比较时忽略大小写和首尾空白，空值和重复在启动时报错。只有新填写的别名受这些约束，旧产品不加别名就可以运行；没有新增的数据库迁移。

locate 会检索名称、标题、别名、嵌套字段的含义、声明的规则和规则标题、实际路由、模块的表、任务和流程。它返回"模块 → 操作 → 步骤和文件位置"，以及继续查看的命令；实际路由按端点引用的约定反查，无法静态解析的动态调用关系是未知的。历史路径必须保留原路由或填写操作别名；不从 Git 历史猜测，也不恢复旧接口。默认返回 10 项、最多 100 项，每项明细最多 12 条并显示省略了多少；表只说明模块归属，实际访问情况未知。操作别名进入计算图、声明摘要和新的运行记录、运行图；旧记录里的别名未知，不用当前声明去补历史。

模块可在 module.py 登记 `owned_tables`（产品负责维护的历史表）和 `external_tables`（只保留）；业务现行表仍登记在 `tables`。关闭入口不撤销表归属。

操作约定可声明QueryBudget；次数/行数/返回大小/重复函数阈值进入启动检查、声明摘要和计算图，接入方式见[数据库](../db/README.md)。

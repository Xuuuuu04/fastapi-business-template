# modules：操作约定、模块声明与启动检查

## 负责

| 文件 | 内容 |
| --- | --- |
| [contract.py](contract.py) | `contract()`：模块对外操作的约定，写在模块的 public.py |
| [module.py](module.py) | `Module`：模块声明，写在模块的 module.py |
| [checks.py](checks.py) | 启动时检查全部模块声明 |
| [catalog.py](catalog.py) | `Catalog`：检查通过后固定下来的模块目录 |

## 为什么这样登记

- 全局只在 `app/setup/catalog.py` 列出启用哪些模块；操作、流程、任务、提示词都写在模块自己的 module.py，只写一次。
- 模块之间的依赖从步骤的 `uses` 推出来，不另外登记，避免两份登记互相对不上。
- 启动检查一次列出全部问题：名称格式、操作归属、权限命名、调用了未启用的模块、循环依赖、表名前缀、提示词文件、任务和定时计划。任一项不通过，服务不会启动。

## 注册检查和资源权限各管什么

注册检查回答“这段代码能不能调用这个操作”；“这个调用者能不能访问这份数据”是资源权限，在业务步骤中用 `caller` 检查，两者都要通过。

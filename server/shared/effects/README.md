# 外部效果

`ProviderSpec`声明HTTP、SMTP或SDK操作及输入输出。产品通过ApplicationSpec组装适配器，凭据只进入配置。`repeat_safe`必须有供应商重复执行保证，单纯提供请求编号并不代表安全。

意图在短事务中保存；领取时先把状态保存为unknown，再在事务外发送；回执在另一短事务保存。发送后退出、取消或保存失败都会保留unknown，不自动回到未发送。原请求和回执使用Vault加密，运行摘要不保存正文。

状态分为not_sent、refused、accepted、completed、unknown，具体语义由适配器定义。SMTP成功仅说明邮件服务器受理，不能证明收件人收到。模拟属性来自适配器，模拟完成不能当作真实发送。参见[Python SMTP说明](https://docs.python.org/3/library/smtplib.html)。

恢复先查询原编号。只有供应商权威确认未执行，或声明可安全重复且旧尝试期限已结束，才能再次发送。未知任务不在启动或迁移时自动发送；不承诺数据库与外部系统之间绝对一次执行。

需要随业务提交后发送时，通过持久任务保存意图编号；任务只发送这个意图，不重新创建另一个请求。跨领域保存沿用原事务。正在执行的调用不占业务写事务。

产品在`ApplicationSpec.providers`登记协议，在`adapters`工厂中组装客户端；业务模块和步骤以`providers`引用同一对象。测试通过`build(..., effect_adapters=...)`显式注入合成适配器，离线配置不执行真实客户端工厂，生产组装拒绝模拟适配器。

适配器必须提供稳定的账号与目标`identity`。HTTP和SDK工厂要求明确传入`account`，SMTP配置也要求账号标识。意图保存其摘要，切换供应商账号或目标后拒绝继续旧请求；凭据轮换仍属于原账号，由产品核对账号配置。

步骤使用`effects.call(spec, input, key=业务键)`在事务外发送；需要随业务提交后发送时，用`@step(saves=True, providers=[spec])`和`effects.enqueue(...)`。意图与普通JobPlan任务同事务保存，worker分发原编号，回滚不留下发送任务。分发需要已登录的可信调用者；匿名业务先建立产品可信身份，不能依靠自报输入冒用其他账号。

`effects.perform(意图编号, lookup=True)`只查询原请求；确认未执行必须带有已校验的查询回执。已受理的结果不能被查询未找到或查询未知改成未执行。旧尝试的迟到回执独立保留，不覆盖新尝试；重复确认已完成的意图不重新发送。原请求、查询与发送回执使用加密字段保存。

运行记录标记发送的供应商、意图编号、耗时与结果，不复制正文到任务表。SQLAlchemy条件领取支持SQLite和PostgreSQL；普通并发限制目前为进程内位置，跨worker资源约束在长流程能力中统一维护。

# records：运行记录

每次执行一个操作都会留下一条运行记录：每一步的状态、耗时、写入字段的摘要、数据说明、大模型调用和出错位置，结束时生成一句中文摘要。它比普通日志更详细，又不保存业务数据原文。

## 文件

| 文件 | 内容 |
| --- | --- |
| [models.py](models.py) | 运行、步骤、大模型与外部接口调用的记录结构 |
| [recorder.py](recorder.py) | 记录器：保存正在执行的运行，结束后交给保存位置 |
| [stores.py](stores.py) | 保存位置：进程内存（有上限）或数据库（多进程共同查询） |
| [tables.py](tables.py) | 数据库保存时使用的表 |
| [summary.py](summary.py) | 按固定句式生成中文摘要，不调用大模型、不猜原因 |
| [values.py](values.py) | 字段摘要：默认只记数量和长度，`log_value` 才记取值，`secret` 从不记录 |
| [evidence.py](evidence.py) | 开发状态与测试历史的固定字段清单，只复制时间、位置、状态和产出形状 |
| [version.py](version.py) | 运行代码的文件摘要，创建服务时计算一次；旧版本成功不当成当前版本成功 |

步骤会同时记录“声明要写的字段”和“实际产出的字段”。发生错误时，之前已经写出的字段仍然可以查看；条件判断另外记录函数、位置、结果和时间。SQL、外部接口、模型调用在所属步骤下面展开。旧的 JSON 记录可以继续读取，缺少的新字段显示未知。

## 规则与原因

- 记录器出错不影响业务：保存失败、缓冲已满只计数，查询时说明“记录不完整”。
- `log_value=True` 的对象或容器含嵌套 `secret=True` 字段时，整项只显示敏感字段提示；不会先序列化再截断。
- 意外异常只记录类型与出错位置，不保留异常消息中的输入值或源码文本。排查时按记录里的步骤、文件和行号检查；已定义的业务错误仍显示其公开原因。
- 运行记录可以丢失和过期清理，业务结果和任务结果以业务表、任务表为准。
- 按 `.env.example` 启动时，本地记录保存在 SQLite；没有设置 `APP_RUN_RECORDS` 时使用内存，重启就会丢。生产环境必须设置 `APP_RUN_RECORDS=database`。
- 长时间没有进展的运行显示“失去联系”，不把没有结束的运行当成成功。
- `/api/system/stats` 按操作和状态汇总已保存的最外层运行；响应同时报告尚未保存或丢失的记录数。
- 数据库模式下，执行进度每三秒按运行编号更新一次，接口进程可以查看后台任务正在执行的步骤。完成后由同一条记录保存最终结果；统计只计算已结束的运行。
- 超过五分钟没有上报的进度显示“失去联系”；这不能证明业务失败，仍需查看任务或业务数据。

query_budget 保存当前额度、已测的总量和未知数量、超额项、以及步骤和存储函数的位置；子操作的累计有上限。旧记录里没有额度时显示未知。测试环境里显式声明的操作超额在提交前失败，生产环境只记录。

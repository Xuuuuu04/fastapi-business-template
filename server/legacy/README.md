# 旧系统迁移

需要复用的旧代码暂放此目录，只由业务模块的 `store/` 导入。设置 `APP_LEGACY_DATABASE_URL` 后，存储构造参数 `legacy` 获得只读数据库入口。旧表使用独立的 `legacy_metadata`，不纳入本项目 Alembic 迁移。先在 `doc/模块名/rules.md` 确认新旧结果样例，再逐步切换读写；迁移完成后删除这里的旧代码。

## 按模块迁移大项目

1. 先选一个能独立说明输入、输出和规则的业务功能。保持旧接口与数据格式，避免同时改业务、数据库和前端。
2. 用 `tools.new_module` 生成固定目录、步骤测试和接口测试。把计算放进步骤；旧数据读取放进 `store/`，外部字段在这里转换成模块的数据格式。
3. 从旧系统记录确认过的输入、输出和失败样例，在隔离的数据副本中比较结果。旧错误不自动当成新规则；时间、随机编号等动态字段按明确规则处理。
4. 运行 `tools.check --module 模块名`，再运行全部检查。查看运行页面的步骤、模块调用和耗时，确认慢在哪里；不要用模块总耗时简单相加计算请求总耗时，因为上层调用包含下层时间。
5. 真实切换前确定可接受的结果、性能和回退条件，再逐个功能切换。模板能减少重复工作，不能保证几十万行旧代码不经分析就自动迁移。

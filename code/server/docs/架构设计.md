# 初版单体架构记录

此文件保留初版实现说明，未完整覆盖后续注册与监控原型。当前讨论以[通用模板设计总稿](../../../docs/通用后端模板设计.md)为入口；实际能力以代码和对应验证记录为依据。

## 1. 职责

| 位置 | 职责 |
| --- | --- |
| app/api | HTTP 输入输出、统一错误、密钥检查、日志关联和 API 文档 |
| app/setup | 创建应用与请求级业务服务 |
| service/notes | 笔记规则、业务数据与事务范围 |
| service/notes/needs.py | 可替换存储操作的约定 |
| service/notes/store | SQLite 实现 |
| shared/config、db、logs、login | 配置、连接、日志和密钥机制 |

单体内通过普通函数和对象调用，没有服务间网络通信。需要数据库的同步接口由 FastAPI 的同步请求处理机制执行。

## 2. 调用过程

请求先经过编号与耗时记录，写入请求检查密钥，然后由路由调用 NoteService。服务通过 NoteStore 约定调用 SqliteNotes。连接按请求创建并关闭，写入由业务事务统一提交或回滚。

业务没有 HTTP 和数据库库依赖。存储实现依赖业务类型；setup 负责将二者组装。没有为纯计算函数额外增加类。

## 3. 数据与约束

笔记含编号、标题、正文、UTC 创建时间。标题去掉首尾空格后要求 1 至 80 个字符，区分大小写且唯一；正文最多 5000 字符。列表按编号倒序分页。

初版所有笔记属于同一个本地示例空间，没有用户归属。读公开，写使用单个共享密钥。更新采用最后一次成功写入的结果，尚无版本冲突检查。

业务数据类型放 types.py，HTTP 类型放 forms.py，SQL 放 store/sqlite.py，数据库结构统一在 shared/db/migrations 中维护。

## 4. 初始化与运行

迁移命令显式建立表。应用创建只注册路由和配置，不连接数据库，所以可以离线导出文档。请求按需访问数据库；未初始化时存活接口正常、就绪接口返回 503。

目前只采用 SQLite，并锁定 Python 与依赖。更换数据库时需增加存储实现和迁移，不能仅修改配置就宣称已支持。

## 5. 检查与限制

测试检查接口行为、标题冲突回滚、持久化、文档、注释以及业务依赖。没有实现后台任务和完整账号体系，也没有生产性能测试。

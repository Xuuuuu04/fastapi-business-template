# 日报迁移样板

这是一个演示。字段和数值都是举例，真实的数据来源、计算规则、单位、空值规则由产品确认。

## 业务

读出当天的两笔订单，计算净销售额，保存日报，旧页面查看和下载。

旧函数 `calculate_net(orders)` 只做计算。例：两笔销售 100.00 元和 50.00 元，一笔退款 20.00 元，净销售额 130.00 元。先用 Decimal 和明确的样例验证这个函数，保留原实现，不要同时改算法。

## 文件安排

生成 `daily_report` 业务包后：

| 位置 | 内容 |
|---|---|
| `store/contract.py`、`store/sql.py` | 声明并实现 `read_orders(day)` 和 `save_report(day, total)`。旧库通过 `legacy` 只读，新库由当前存储保存 |
| `steps/read_orders.py` | 声明读 day、写 orders。通过 store 读数据，转换单位和字段 |
| `steps/calculate_report.py` | 放入独立的 `calculate_net`。正式的 `@step` 声明读 orders、写 total，执行 `data.total = calculate_net(data.orders)` |
| `steps/save_report.py` | 声明读 day 和 total、写 report。在新框架的事务里保存，失败时保留明确的错误 |
| `flow.py` | 定义 读取 → 计算 → 保存 的流程，结果是 report |
| `app/api/v1/daily_report.py` | 把旧路径和旧返回格式转换成正式的公开操作，接上旧页面的查看和下载 |
| `tests/modules/daily_report/` | 用确认过的样例测试异常、日期范围和兼容规则 |

如果旧函数自己查库、请求外部平台或 commit，不能直接放进计算步骤。把纯计算部分提取出来，其余按上表改写。拆开的成本太高时，可以重写这个功能，但仍要保留"相同输入、相同输出"的比较。

## 验证

1. 在隔离的数据上比较这几种情况：正常例（130.00 元）、当天没有订单、缺字段、退款超过销售额、跨日期、保存失败。每种情况的预期由产品确认，不能自己把未知或缺失当成 0。
2. 在同一份代码里实际调用旧接口，打开页面查看并下载，对比页面和文件里的日期、单位、结果。

## 完成条件

当前这项业务完成，指：

- 日报的数据范围正确；
- 计算和保存正确；
- 必要的权限和事务检查通过；
- 旧页面能查看、能下载。

完整的容量测试、其他业务的自动清理、全项目的恢复演练，作为最终要求另列。但只要问题会影响这份日报的数据安全，就必须在这项业务投入使用前解决。

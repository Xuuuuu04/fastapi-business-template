# 前后端隔离验收

在 `server/` 执行：

```bash
uv run dev acceptance-server --port 0 --run-id 本轮编号
uv run dev acceptance-server --port 0 --run-id 本轮编号 --seed
uv run dev acceptance-server --port 0 --run-id 本轮编号 --lifecycle-file /本轮报告目录/backend.json
```

本轮编号只用英文字母、数字、下划线和连字符，最多 80 字。端口为 0 时由系统分配；只监听 `127.0.0.1`，指定的端口已被占用时直接失败，不复用已有服务。启动记录中的 `acceptance_starting` 只表示准备完成，调用方仍须请求 `/health/ready`，核对成功状态和 `X-Acceptance-Run` 响应头。

`--lifecycle-file` 指向调用方已经创建的报告目录中的新文件，不能覆盖已有文件。服务在创建临时目录后原子写入 `run_id`、`folder` 和 `phase: "created"`；关闭临时目录并确认删除成功后，再原子更新为 `phase: "cleanup_complete"`。启动后的准备失败也会执行清理。目录删除失败时保留未完成状态并使进程失败，调用方必须核对本轮编号、目录和完成状态，不能仅凭进程退出认定清理成功。

## 数据与身份

配置使用产品的 `ApplicationSpec.settings("test")`，不读取配置文件或环境变量。产品 `configure` 运行之后，再检查环境、数据库、文件目录、远程配置等是否符合隔离要求；种子准备之后重新检查。模板拒绝自定义外部供应商、适配器与模型工厂，不能用它验证这些外部调用。产品自己的扩展代码与种子函数是可信测试代码，本命令不提供网络或系统权限隔离。

数据库是本轮创建的 SQLite，按照已登记表的元数据创建结构，并写入当前结构版本供就绪检查使用。没有运行迁移文件，也没有验证 PostgreSQL 并发与兼容性；这两项仍按原有迁移和数据库测试执行。后台 worker 不随 HTTP 服务启动，不能据此宣称后台任务已验收。

`--seed` 只加载产品的 `server/tests/acceptance/seed.py`，其中提供 `async prepare(services, folder)`。函数使用传入的本轮服务与目录准备合成账号和数据，缺文件或函数不是异步函数时失败。默认不加载该文件，不添加测试专用生产接口。需要让浏览器读取合成账号时，把本轮凭据写在传入目录中，权限设为仅当前用户可读，测试结束自动清除；不把真实凭据、访问令牌和密码写入日志、报告或截图。

## 执行与完成

1. 调用方记录启动的进程与本轮编号，等待真实就绪并核对响应头。
2. 浏览器通过产品实际登录和页面完成业务操作，再通过正式查询核对结果；保留实际验证的场景与前后端版本。
3. 正常结束、断言失败和用户中断时，都向自己启动的进程发送 SIGTERM 或 SIGINT，并等待它退出。服务关闭连接并删除本轮临时数据库与文件。
4. 核对进程已退出且本轮目录已删除，清理失败时本轮不能报告通过。报告保存在本轮目录之外，默认不保存包含身份信息的浏览器 trace。

强制终止或机器掉电不能执行清理；调用方应记录本轮目录并在确认进程退出后清理自己创建的目录，不按通配符删除其他验收实例。

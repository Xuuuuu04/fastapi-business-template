# 检查来历与删除条件

本表说明命名检查为什么存在。检查通过只对本次源码、范围与数据库负责，不能代替业务验收。每项业务样例的输入和预期来自规则与独立资料；源码注释说明样例用途，检查原件保存实际执行事实。

删除条件共同适用：先确认原来的要求已经取消，或替代实现与独立反例已经覆盖同一风险；写明受影响的行为与当前证据，审查后再删除。模型能力提升可以作为删除理由，但要附固定评测的前后对比；以前通过过、测试太慢不能作为删除依据。阈值改动仍属于框架变更；无效的例外会由 `unused_exception` 提醒清除。

| 命名检查 | 来历、用途与专项删除条件 |
| --- | --- |
| `blocking_call` | 异步请求中的同步等待会占住事件循环；仅在相应调用已移到异步实现或明确的后台执行位置后调整范围。 |
| `file_header`、`class_comment`、`function_comment` | 保留用途和定位入口，避免只能猜测实现；替代文档必须能定位同一源码责任。 |
| `file_lines`、`function_lines`、`nesting`、`comment_run`、`todo` | 约束难以维护的组织和过期文字；当前上限是已声明的工程约定，变更时同时复核可读性和真实差异。 |
| `module_name`、`name_format`、`name_vague`、`step_name`、`condition_name` | 名称参与项目图、操作与源码定位；只有对应的命名或定位机制已经迁移才能替换。 |
| `readme_missing`、`readme_lines`、`readme_operation`、`readme_section` | 目录职责和公开操作供接手者发现；替代入口必须覆盖同一目录及实际公开操作。 |
| `missing_module`、`not_listed`、`not_exposed`、`unused` | 模块登记、实际HTTP/后台入口与内部调用相互核对；不能用登记数量代替可调用性。 |
| `doc_missing`、`doc_index`、`doc_lines`、`rule_missing` | 需求、规则、变化和目录需要共同维护；只有明确取消相应业务资料责任时才能删除。 |
| `doc_generated` | API、流程、账本生成段和入口摘要必须匹配当前声明；新生成器须有真实过期和手写保留反例。 |
| `confirmed_case`、`simulated_implementation` | 防止修改已确认预期或把模拟骨架作为完成；确认修订和原话依据不能被替代为测试成功。 |
| `ledger_recovery` | 写入中断必须恢复明确原件，不能读取半份规则；只有替代存储证明异常和进程退出恢复后才可退役。 |
| `glossary_target`、`writing_style` | 统一业务词和可读说明；词义变更必须连同实际操作、规则与文档适配。 |
| `unused_exception` | 例外失效后自动清理，避免长期放宽范围；没有例外时保持为空。 |

## 检查流程与运行约束

| 检查 | 依据与删除前需要替代的验证 |
| --- | --- |
| 代码风格、格式、类型 | 当前工具配置，开发入口与生产代码都参与；新工具须处理现有真实错误，不能只减少检查文件。 |
| 包布局、依赖方向、公开入口、字段读写 | 标准包、纯工具及流程责任；替代架构须证明跨包调用、纯计算与事务边界仍符合要求。 |
| 表归属与迁移一致性 | 只修改本产品拥有的结构，保护外部和旧表；必须保留归属反例及双库增量/全新验证。 |
| SQLite/PostgreSQL样例 | 两类数据库有不同的约束、权限与并发语义；取消一个数据库支持时才能删除对应轮次，跳过不能算通过。 |
| 当前源码、整链范围、缓存和不稳定历史 | 防止旧记录、局部结果或失败历史被当作当前成功；新证据实现须证明版本、范围、引用与失败事实完整。 |
| 时间、事务、外部意图、资源、分段与重启恢复 | 来自已声明的有效期、保存边界、未知写入及恢复要求；只在相应能力明确退役时删除，或用新实现的独立样例替换。 |
| 新项目、三方升级、临时整合、生产镜像 | 用户实际采用模板的路径；仅改变接口时替换用例，保留应用前失败不改原件与生产安装不依赖外部开发目录的验证。 |

当前命名检查实现位于 `scripts/fastapi_check/quality/`；检查流程在 `check.py`、`matrix.py`。运行声明检查位于 `server/shared/modules/validation/`，具体能力的独立样例在 `server/tests/`。删除记录写入对应提交或产品变化说明，不把一次性的任务流水放进项目长期入口。

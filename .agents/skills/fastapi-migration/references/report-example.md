# 日报迁移样板

演示业务：读出当天两笔订单，计算净销售额，保存日报，旧页面查看和下载。这里的字段与数值是演示，实际来源、计算规则、单位、空值规则由产品确认。

旧函数 `calculate_net(orders)` 只计算：两笔销售 100.00、50.00 元，退款 20.00 元，结果 130.00 元。先用 Decimal 和明确样例验证，保留这个计算实现。不要同时改成新算法。

生成 `daily_report` 业务包后按下面安排：

| 位置 | 实现 |
|---|---|
| `store/contract.py`、`store/sql.py` | 声明并实现 `read_orders(day)` 和 `save_report(day, total)`；旧库从 `legacy` 只读，新库由当前存储保存 |
| `steps/read_orders.py` | 声明读 day、写 orders；通过 store 读数据，转换单位与字段 |
| `steps/calculate_report.py` | 放入独立 `calculate_net`；正式 `@step` 声明读 orders、写 total，执行 `data.total = calculate_net(data.orders)` |
| `steps/save_report.py` | 声明读 day/total、写 report；在新框架事务内保存，失败保留明确错误 |
| `flow.py` | 定义 read→calculate→save 的 Flow，结果为 report |
| `app/api/v1/daily_report.py` | 旧路径与返回模型转换到正式公开操作，接入旧页面查看和下载 |
| `doc/daily_report/rules.md` | 保存确认样例、异常、日期范围与兼容规则；测试预期来自这里 |

混合旧函数如果自己查库、请求平台或 commit，不直接放进计算步骤；提取纯计算，其余能力按上述位置改写。拆分成本过高时可重写当前功能，但仍保留相同输入输出的比较。

先在隔离数据比较：130.00 元正常例、无订单、缺字段、退款超过销售、跨日期、保存失败。每例预期由产品确认；不能自行把未知或缺失变成 0。然后在一个共同版本实际调用旧接口，打开页面查看并下载，核实页面和文件中的日期、单位与结果。

当前业务完成条件为这张日报的来源范围正确、计算/保存正确、必要权限事务通过、旧页面查看下载可用。完整容量、其他业务的自动清理与全项目恢复另列最终要求。涉及本日报数据安全的恢复或清理问题仍须在当前业务使用前解决。

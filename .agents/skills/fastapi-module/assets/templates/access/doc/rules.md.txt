# $title：规则

> 每条规则一个编号，代码中的 rule="R-xx" 必须能在这里找到对应标题。写清楚计算方法、异常情况和确认样例。
> 字段的含义、单位和空值说明写在代码的 `meaning()` 中，计算流程由代码生成，两者都见 [flows.md](flows.md)；这里只写规则本身。

## 规则

### R-01 登录核对

组织代码、账号、口令都对才能登录。账号不存在和口令不对返回同一个错误 `${name}_login_failed`（401），不说明是哪一项。同一组织里账号不能重名。

| 输入 | 结果 |
| --- | --- |
| 组织代码、账号、口令都对 | 返回访问令牌、Bearer、有效秒数和组织代码 |
| 口令不对 | 401，`${name}_login_failed` |
| 账号不存在 | 401，`${name}_login_failed` |
| 同一组织里再建同名账号 | 409，`${name}_account_exists` |

### R-02 口令保存

新建账号的口令 8 到 256 个字符。只保存随机盐和 scrypt 摘要，比较用固定时间；口令计算受 `APP_HEAVY_CONCURRENCY` 限制同时计算的数量。

### R-03 权限范围

权限写成“模块名.动作”或“模块名.*”，`*` 表示全部权限。登录时把账号权限写进访问令牌，令牌有效期内不变。新建账号只能在调用者自己的组织里建（调用者组织为 `*` 时不限），授予的每一项权限调用者自己都要有，否则 403，`${name}_grant_denied`。

### R-04 登录失败限流

15 分钟内，同一来源地址对同一账号失败 `APP_LOGIN_FAILURE_LIMIT` 次（默认 5），或同一账号来自所有地址失败 `APP_LOGIN_ACCOUNT_FAILURE_LIMIT` 次（默认 20），之后的登录直接返回 429。登录成功后两项计数清零。多个接口进程要共享计数时配置 `APP_CACHE_URL`。

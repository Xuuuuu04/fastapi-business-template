# $title：需求

> 本文件记录已经确认的业务需求。未确认的内容标注“待确认”，不要由 AI 自行补全。

## 谁使用

产品的登录用户：在前端登录页填写组织代码、账号和口令，换取访问令牌。账号由有 `$name.manage` 权限的管理者新建。

## 要解决什么问题

让前端模板的登录页直接接上真实后台，登录后按令牌里的权限决定能看到和能做的事。

## 功能

| 功能 | 说明 | 对应操作 |
| --- | --- | --- |
| 登录 | 核对组织代码、账号和口令，签发访问令牌 | $name.login |
| 新建账号 | 管理者在自己的组织里新建账号，授予不超出自己的权限 | $name.create_account |

## 第一个管理账号

用服务密钥建：`uv run dev make-key --name 账号管理 --org-id 组织代码 --permissions $name.manage`，把输出的摘要配置进 `APP_API_KEYS`，再带上 `X-API-Key` 调用 `POST /api/v1/access/accounts`。

## 明确不做

- 角色、停用账号、修改和找回口令、刷新令牌、退出登录、两步验证。需要时产品按自己的规则增加，并在 rules.md 写清楚。
- 当前用户接口。前端只读取登录回包和令牌里的 `permissions`。
